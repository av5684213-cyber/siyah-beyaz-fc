# Görev 6: Fix Rental Loan Error ("Oyuncu bulunamadı")

## Summary
Fixed the rental loan system where `loanWeeks` state existed in the frontend but was never sent to the `/api/rental/list` API endpoint.

## Changes Made

### 1. `src/components/fm/PlayerDetailModal.tsx` (lines 1611-1621)
- Added `durationWeeks: loanWeeks` to the fetch body in the loan form submission handler
- Updated console.log to include `durationWeeks` for debugging
- The `loanWeeks` state (default: 17) was already defined at line 155 but never passed to the API

### 2. `src/app/api/rental/list/route.ts`
- Updated API doc comment to include `durationWeeks` in the body spec
- Destructured `durationWeeks` from request body (default: 17)
- Added validation: `durationWeeks` must be 1-34
- Added `duration_weeks` field to `rental_listings` insert
- Added fallback: if `rental_listings` insert fails (e.g., column doesn't exist), retries without `duration_weeks`
- Added `duration_weeks` field to `loans` table insert
- Included `durationWeeks` in the success response
- Improved "Oyuncu bulunamadı" error messages with more context and debug info

### 3. `supabase-migration.sql`
- Added `duration_weeks INT NOT NULL DEFAULT 17` column to `rental_listings` CREATE TABLE
- Added `ALTER TABLE rental_listings ADD COLUMN IF NOT EXISTS duration_weeks` for existing databases

## Root Cause Analysis for "Oyuncu bulunamadı"

The error occurs when the player doesn't exist in the Supabase `players` table. Possible causes:
1. **Player not synced**: Player created locally but not yet saved to Supabase
2. **Missing columns**: The full select query includes `is_on_loan_market` and `loan_status` columns which may not exist yet — code already has fallback for this
3. **ID format**: Player IDs are generated by `Math.random().toString(36).substring(2, 11)` and stored as TEXT — format matches between frontend and database
4. **No ownership validation**: Unlike `/api/loans/list`, the `/api/rental/list` route doesn't verify the player belongs to the requesting user
